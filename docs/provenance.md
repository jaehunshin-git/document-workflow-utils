# 출처 및 구현 경계

## 목적

이 저장소는 회사 업무에서 반복적으로 발생하는 파일 검증 시간을 줄일 필요성을 바탕으로, 일반화한 요구사항을 개인적으로 다시 구현한 포트폴리오입니다. 특정 업무 환경의 산출물을 옮기는 것이 아니라, 일반화 가능한 문제를 독립적으로 풀어 본 결과만 담습니다.

## 클린룸 원칙

- 구현은 공개적으로 설명 가능한 요구와 개인적인 문제 정의를 바탕으로 새로 작성합니다.
- 외부 조직의 소스, 문서, 설정, 데이터, 디자인 자산, 식별 정보, 내부 경로를 참고 자료나 구현물로 반입하지 않습니다.
- 외부 환경에서 기억한 구체적 구현 세부나 파일 구조를 재현하지 않고, 이 저장소의 목적에 맞는 별도 설계와 명명 규칙을 사용합니다.

## 포함 범위

- 숫자 요약, 중복 식별, 입력 간 비교, 경로 구조 출력처럼 일반화한 유틸리티 기능
- 해당 기능을 실행하기 위한 `doc-utils` 명령줄 인터페이스
- 공개 가능한 사용 방법, 설계 의도, 검증 코드와 설정

## 제외 범위

- 외부 조직의 코드, 데이터, 로고, 문서 원본, 구성 정보, 내부 경로
- 실제 업무에서 생성되었거나 취득한 파일과 그 파생물
- 외부 환경의 접근 정보, 식별자, 비공개 규칙

## 합성 데이터 정책

예제와 테스트에 쓰는 모든 데이터는 기능 검증을 위해 새로 만든 합성 데이터입니다. 실제 인물, 고객, 조직, 업무 기록 또는 운영 데이터를 복사하거나 변형해 사용하지 않습니다. 합성 데이터는 의미 있는 식별 정보를 포함하지 않으며, 공개 저장소에 올려도 되는 범위로만 유지합니다.

## 기존 코드 및 이력 미이전 검증 원칙

- 새 파일은 이 저장소에서 처음 작성하고, 다른 저장소의 파일·커밋·이력을 가져오지 않습니다.
- 변경을 검토할 때 외부 코드 조각, 고유한 식별자, 내부 경로, 실제 데이터가 포함되지 않았는지 확인합니다.
- 예제와 테스트는 합성 데이터임을 확인하고, 공개 범위에 맞지 않는 내용은 추가하지 않습니다.
- 구현 근거와 변경 이력은 이 저장소 안에서 독립적으로 설명 가능해야 합니다.
