# 설계 의사결정

이 문서는 파일 검증 도구가 자동화 환경에서 예측 가능하고 안전하게 동작하도록 선택한 기준을 설명합니다.

## 결정적 정렬

파일과 결과는 대소문자를 정규화한 키와 원문을 차례로 비교해 정렬합니다. 같은 입력에는 운영체제의 디렉터리 반환 순서와 관계없이 같은 텍스트·JSON·CSV 결과가 생성됩니다.

## 심볼릭 링크 제외

디렉터리 탐색에서는 심볼릭 링크를 따라가지 않습니다. 순환 링크로 인한 무한 탐색과 지정한 루트 밖의 파일이 결과에 섞이는 상황을 함께 방지합니다.

## 운영체제 생성 파일 제외

`desktop.ini`는 대소문자와 Windows 경로 구분자를 고려해 기대 목록과 실제 디렉터리 모두에서 제외합니다. 업무 파일 검증에 운영체제 메타데이터가 노이즈로 포함되지 않게 하기 위한 정책입니다.

## 종료 코드 정책

기대 파일이 누락되면 종료 코드 1을 반환해 CI나 셸 스크립트가 검증 실패를 감지할 수 있습니다. 기본 비교에서는 추가 파일을 보고하되 성공으로 처리하고, `--strict`에서는 누락과 추가를 모두 실패로 처리합니다. 잘못된 인자와 입출력 오류는 종료 코드 2로 구분합니다.

## 정수 범위 상한

누락된 모든 정수를 계산하는 기능은 최솟값과 최댓값의 차이를 1,000,000으로 제한합니다. 입력 두 개만으로 과도한 CPU와 메모리를 소비하는 상황을 방지하며, 제한 초과는 사용 오류로 명확히 보고합니다.

## 런타임 의존성 0개

핵심 기능은 Python 표준 라이브러리만 사용합니다. 설치 비용과 공급망 노출을 줄이고, 작은 자동화 도구라는 프로젝트 목적에 맞는 배포 단위를 유지합니다. 테스트·정적 검사·빌드 도구는 개발 의존성으로만 분리합니다.

## JSON 자동화 인터페이스

모든 하위 명령은 사람이 읽는 기본 출력과 구조화된 JSON 출력을 함께 제공합니다. `schema_version`과 `command`를 모든 결과에 포함하고 JSON 키 정렬과 UTF-8 문자를 보존해 계약 검증과 다른 프로그램의 후속 처리에서 안정적으로 사용할 수 있게 합니다.

## Ignore 패턴

디렉터리 기반 명령은 반복 가능한 ignore 패턴을 받습니다. 패턴은 루트 기준 POSIX 상대경로에 적용해 운영체제와 무관한 실행 결과를 만들고, 제외된 디렉터리의 하위 항목도 함께 탐색하지 않습니다.

## 기대 목록의 경로 경계

기대 파일 목록의 백슬래시, 중복 구분자와 현재 디렉터리 표시는 POSIX 상대경로로 정규화합니다. 절대경로와 `..` 구성 요소는 비교 루트 밖을 가리키는 모호한 입력이므로 거부합니다.

## 확장자 통계

확장자는 파일명의 마지막 점을 기준으로 소문자화해 집계합니다. `archive.tar.gz`는 `.gz`에 포함하며, 확장자가 없거나 `.env`처럼 이름 전체가 점으로 시작하는 파일은 빈 문자열 키로 집계합니다. 이 규칙은 Python `pathlib`의 의미와 일치합니다.

## 배포물 독립 검증

CI는 소스 트리 테스트뿐 아니라 빌드된 wheel을 새 가상환경에 설치합니다. 소스 경로와 사용자 패키지를 격리한 상태에서 `doc-utils`와 `python -m document_workflow_utils` 진입점, JSON 계약, 종료 코드 및 PEP 561 `py.typed` 포함 여부를 검증해 소스에서는 통과하지만 배포물에서는 실패하는 문제를 차단합니다.

wheel과 sdist의 배포 메타데이터에는 README 본문이 포함되므로 권리 유보 안내도 함께 전달됩니다. 템플릿에만 적용되는 MIT 고지가 프로젝트 배포물의 라이선스로 오인되지 않도록 `.github`는 sdist에서 제외합니다. 스모크 검증은 두 산출물의 권리 안내와 제외 정책을 확인하며, 별도의 오픈소스 라이선스를 부여하지 않습니다.
